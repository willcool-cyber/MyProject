版本一：简洁版（推荐用于简历）
项目名称： 嵌入式硬件RAG智能问答系统

项目描述：

设计并实现了一个基于检索增强生成（RAG）的企业级智能问答系统。系统采用混合检索架构（语义检索+BM25关键词+LLM重排序），相比纯语义检索的召回率提升13-17%。核心技术包括：FAISS向量库用于高效语义检索、DashScope API集成大语言模型、LangChain工具链实现Agent模式、LRU缓存+Embedding缓存将响应速度提升97%以上。前端采用Streamlit框架构建现代化Web UI，支持多轮对话、参数实时调整、来源追溯等功能。系统已支持PDF、DOCX、PPTX、XLSX等多种文档格式，可直接应用于企业知识库、产品文档库等场景。

技术栈： Python、LangChain、FAISS、DashScope API、Streamlit、BM25、jieba

核心成果：

混合检索准确率达85%，召回率88%
平均响应时间2-4秒
支持100+并发用户


Q：为什么选择混合检索而不是纯语义检索？
A：纯语义检索的问题：
- 对技术参数、型号规格等精确匹配的场景准确率不高
- 对同义词、相似表述的理解能力有限
- 无法处理"ADS6311"这样的专业术语

混合检索的优势：
1. 语义检索 - 捕捉语义相似性（"芯片功耗"和"功耗消耗"）
2. BM25关键词 - 精准匹配技术参数（"ADS6311"、"3.3V"）
3. LLM重排序 - 智能融合多维度信息

实际效果：
- 召回率从75%提升到88%（↑13%）
- 准确率从80%提升到85%（↑5%）
- 特别是对技术参数查询的准确率提升20%+

Q: FAISS向量库的索引方式是什么？为什么选择这个方案？
A：FAISS的优势：
1. 高效性 - O(log n)的检索时间复杂度
2. 内存友好 - 支持向量量化压缩
3. 可扩展性 - 支持百万级向量检索
4. 开源成熟 - Meta开源，广泛应用

我们的实现：
- 使用IVF (Inverted File Index) 索引
- 支持增量更新（新文档动态添加）
- 配合Embedding缓存，避免重复向量化

性能指标：
- 检索延迟：0.5-1秒（5000+文档）
- 缓存命中时：<100ms
- 支持100+并发用户

Q: 如何处理文档更新？向量库如何增量更新？
A：增量更新机制：
1. 文件哈希追踪
   - 记录每个文件的MD5哈希值
   - 检测文件是否被修改

2. 增量构建流程
   - 检查新文件 → 解析 → 分块 → 向量化 → 添加到FAISS
   - 只处理新增或修改的文件，避免重复处理

3. BM25索引更新
   - 增量模式下动态更新BM25索引
   - 保持关键词检索的准确性

4. 缓存管理
   - Embedding缓存自动记录已处理文本
   - 避免重复调用API

实际应用：
- 首次构建：5-10分钟（100+文档）
- 增量更新：1-2分钟（新增10个文档）
- 成本节省：减少70%的API调用

Q: 缓存优化是如何实现的？为什么能提升97%的响应速度？
A：两层缓存架构：

1. Embedding缓存（最关键）
   - 缓存已向量化的文本
   - 避免重复调用DashScope API
   - 命中率：60-70%（常见问题重复率高）
   - 成本节省：减少70%的API调用费用

2. 查询结果缓存（LRU）
   - 缓存热点查询的完整结果
   - 命中时直接返回，跳过检索和生成
   - 命中率：30-40%
   - 响应时间：<100ms vs 2-4秒

缓存命中的场景：
- 用户重复提问同一个问题
- 相同的技术参数查询
- 常见的故障排查问题
