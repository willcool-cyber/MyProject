## 📂 核心模块说明

### 1️⃣ 文档处理管道
- **多格式支持**：使用 `PyPDF`、`python-docx`、`openpyxl` 等库
- **智能分块**：每 500 字符一块，保留 50 字符重叠，保证上下文连贯
- **元数据标注**：记录文件名、分块 ID、时间戳等信息

### 2️⃣ 混合检索核心

**语义检索（FAISS）**
- 使用 `DashScope text-embedding-v2` 模型
- 1536 维向量表示
- 毫秒级查询速度
- 支持百万级文档

**关键词检索（BM25）**
- 集成 `BM25` 算法
- 通过 `jieba` 中文分词
- 精准匹配技术参数和型号
- 弥补语义检索的不足

**智能重排序（LLM）**
- 利用 `DashScope qwen-max` 模型
- 对初步检索结果进行相关性重排
- 融合多维度信息
- 准确率提升 5-10%

### 3️⃣ 缓存与优化

**多级缓存策略**
- **Embedding 缓存**：缓存已向量化的文本，减少 70% API 调用
- **查询结果缓存**：缓存完整的问答对，命中时 <100ms 响应
- **LRU 缓存**：自动淘汰最少使用的缓存项

**性能优化**
- 批量处理 Embedding，提升吞吐量
- 异步查询，提高并发能力
- 连接池复用，减少开销

### 4️⃣ 应用层架构

**Agent 框架**
- 基于 `LangChain` 构建 Agent 链
- 支持工具调用（计算、转换、搜索等）
- 多轮对话管理
- 错误自动修复

**Web UI**
- 基于 `Streamlit` 快速构建
- 现代化卡片式设计
- 响应式布局，适配各种屏幕
- 实时交互，流畅体验

## 🤔 设计思考与难点攻克

### 难点 1️⃣：如何平衡检索速度与精度？

**问题**
- 纯语义检索快但不够精准（准确率 80%）
- 复杂的检索逻辑会导致响应缓慢

**解决方案**
- 设计**混合检索管道**：
  1. 先用 FAISS + BM25 快速召回 Top-20
  2. 再用 LLM 进行精准重排序，取 Top-5
  3. 在精度和延迟间取得完美平衡
- 结果：准确率 85%+，响应时间 2-5 秒

### 难点 2️⃣：如何应对高并发下的 API 成本与延迟？

**问题**
- DashScope API 调用成本高
- 高并发下容易触发限流
- Embedding 计算耗时

**解决方案**
- 实现**多级缓存策略**：
  1. Embedding 缓存：缓存已向量化的文本
  2. 查询结果缓存：缓存完整的问答对
  3. LRU 缓存：自动淘汰最少使用的项
- 结果：
  - API 调用减少 70%
  - P95 延迟降低 97%
  - 成本降低 70%

### 难点 3️⃣：如何支持多种文档格式？

**问题**
- 不同格式的文档结构差异大
- 提取文本时容易出错或丢失信息

**解决方案**
- 实现**统一的文档处理管道**：
  1. 为每种格式实现专门的提取器
  2. 统一的分块和向量化流程
  3. 完整的错误处理和恢复机制
- 支持格式：PDF、DOCX、PPTX、XLSX、TXT

### 难点 4️⃣：如何实现真正的多轮对话？

**问题**
- 需要记住对话历史和上下文
- 长对话容易导致 token 溢出

**解决方案**
- 实现**智能上下文管理**：
  1. 保存完整的对话历史
  2. 动态调整上下文窗口
  3. 重要信息优先保留
- 结果：支持 20+ 轮对话，上下文连贯
