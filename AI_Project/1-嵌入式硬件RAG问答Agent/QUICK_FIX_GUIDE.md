# 快速修复指南

## 问题症状

✗ 新文件放入 `data` 文件夹后
✗ 运行 `RAG数据库.py` 成功解析
✗ 但启动 `main.py` 后无法回答新文件中的问题

## 快速修复（3步）

### 第1步：清理旧的向量库配置

```bash
# 删除旧的配置文件，强制重建
del src\embedding向量库\config.json
```

**为什么**: 旧的配置文件中没有记录新文件，需要重新生成

### 第2步：启动应用进行完全重建

```bash
python main.py
```

选择 **1️⃣  终端查询模式**

系统会自动：
1. 检测到配置文件缺失
2. 进行**完全重建**（处理所有文件）
3. 更新 FAISS 和 BM25 索引
4. 保存新的配置文件

**预计时间**: 5-10分钟（取决于文件大小）

### 第3步：验证修复

启动后，在终端中测试查询：

```
🤔 请输入问题: ADS6311芯片有什么特点？
```

如果能得到回答，说明修复成功！

## 修复原理

| 步骤 | 修复内容 | 效果 |
|------|---------|------|
| 删除配置 | 清除旧的已处理文件记录 | 强制重新扫描所有文件 |
| 完全重建 | 处理所有文件（包括新文件） | 新文件被向量化 |
| 更新索引 | FAISS + BM25 索引更新 | 新文件内容可被搜索 |

## 常见问题

### Q1: 完全重建需要多长时间？
**A**: 取决于文件大小，通常 5-10 分钟。大型PDF可能需要更长时间。

### Q2: 能否跳过完全重建，只处理新文件？
**A**: 可以。修复后的系统会自动检测新文件并增量更新。只需重新启动 `main.py` 即可。

### Q3: 删除配置文件会丢失什么？
**A**: 不会丢失任何数据。只是删除了"已处理文件"的记录，系统会重新生成。

### Q4: 如何确认新文件被正确处理？
**A**: 
1. 运行 `test_new_file_detection.py` 检查
2. 或在启动时查看日志中是否显示新文件被处理

### Q5: 修复后还需要做什么？
**A**: 无需做任何事。系统会自动：
- 检测新文件
- 增量更新向量库
- 保存配置
